有监督微调 (Supervised Fine-Tuning, SFT) 用高质量示例教模型遵循指令、格式与目标行为，是让预训练基座模型转化为可用助手的第一个关键阶段。它承接 [预训练](./pre-training.md) 的 next-token prediction 目标，只是把训练分布从海量通用语料收窄为「指令 -> 目标回答」的结构化数据；这一步产出的模型又会作为 [偏好优化](./preference-optimization.md) 与 [RLHF](./rlhf.md) 的初始策略，因此其质量直接决定上游阶段的天花板。把 SFT 纳入标准后训练流水线的代表工作是 [InstructGPT](https://arxiv.org/abs/2203.02155)：先由人类示范做 SFT，再训练奖励模型，最后用强化学习继续优化。

## 快速开始

第一步是固定「聊天模板」。同一份数据在训练和上线时必须以完全一致的方式渲染成 token 序列，否则会出现训练-推理分布漂移，表现为格式错乱或回复不完整。选定模板后，把每个样本编码为 `input_ids` 与 `labels`，并只对目标回复（通常是 assistant 部分）计算损失，将用户 prompt 与系统提示位置设置为忽略。由于 SFT 与预训练共享同一个条件语言建模目标，损失仍是对目标 token 的负对数似然：

$$
\mathcal{L}_{\text{SFT}} = -\sum_{t \in \mathcal{T}} \log \pi_\theta(y_t \mid x, y_{<t})
$$

其中 $x$ 是 prompt，$y_{<t}$ 是已生成前缀，$\pi_\theta$ 是当前策略（即被微调的语言模型），$\mathcal{T}$ 是需要计算损失的目标 token 位置集合（即 assistant 回复部分）。prompt 与系统提示位置不进入 $\mathcal{T}$，实现上通常把它们的标签置为 `-100` 并配合 `ignore_index=-100` 忽略。一个最小掩码示例如下：

```python
prompt_ids = tokenizer.apply_chat_template(messages[:-1], tokenize=True)
full_ids = tokenizer.apply_chat_template(messages, tokenize=True)
labels = full_ids.clone()
labels[: len(prompt_ids)] = -100  # prompt 与系统提示不参与损失
# loss = F.cross_entropy(logits, labels, ignore_index=-100)
```

第二步是配置关键超参数。SFT 的学习率通常比预训练小一个数量级（常见在 1e-5 到 1e-4 区间，以所用框架与模型的官方建议为准），训练轮数一般控制在 1 到 3 轮，轮数过多容易过拟合到示例表面措辞。批大小受显存约束时，可与梯度累积配合保持有效批大小稳定。使用 [TRL 的 SFTTrainer](https://huggingface.co/docs/trl/sft_trainer) 等成熟实现时，模板、掩码与打包（packing）逻辑通常已内置，但仍应检查其与自有数据的渲染是否一致。

第三步是先做小样本冒烟训练：取几十条数据跑若干步，检查损失是否下降、梯度是否正常，并解码若干样本确认渲染后的完整对话、标签掩码与输出格式都符合预期，再扩展到全量训练。验证成功与否的判断标准是：损失平稳下降，且随机抽样的回复能遵循指定格式。

## 数据要点

示例的质量、覆盖面与一致性通常比单纯数量更重要。质量指回答正确、语气自然、无事实错误；覆盖面指指令类型多样，涵盖问答、摘要、改写、代码、结构化输出等；一致性指同类问题在格式、术语与风格上统一，避免模型学到相互矛盾的信号。这与「数据越多越优」的直觉相反：噪声样本会通过梯度污染放大到所有同分布样本上，因此清洗往往比堆量更有效。

数据必须与上线格式对齐。系统提示、工具调用（function calling）格式、多轮上下文都要用生产环境的真实结构来构造，而不是训练一种格式、上线另一种格式。多轮对话的损失可以只计算最后一轮回复，也可以对每一轮 assistant 回复都计算，前者更利于收敛到「只答当前问题」，后者更利于保持多轮上下文一致性，需按任务取舍。

数据准备还要做去重、清洗与评测集防泄漏。重复样本会放大某些模式的权重，脏数据（截断、乱码、非目标语言）会污染分布；同时应剔除与评测基准重合的样本，否则评估结果会虚高。SFT 的局限在于它只模仿给定答案：即使数据包含多轮动作与观察，模型也不会因为任务最终成功或失败而重新评价每一步动作。因此 SFT 模型通常只作为后续 [偏好优化](./preference-optimization.md) 与 [RLHF](./rlhf.md) 的起点，真正把「结果好坏」纳入训练的闭环由强化学习阶段完成。

## 案例

以「用户问题 -> JSON 答案」的结构化输出任务为例。数据集中每一条是 `{question, answer_json}`，先统一用同一模板渲染为对话文本，再编码并把 prompt 与问题部分的 label 掩码掉，只对 JSON 答案部分计算交叉熵损失。

训练完成后，用未见过的测试问题生成答案，评估两个指标：JSON 可解析率（能否被 `json.loads` 正确解析）与内容正确率（字段是否齐全、取值是否正确）。若可解析率不达标，优先检查模板在训练与推理是否一致、系统提示是否明确；若内容正确率低，则回头审视数据质量、覆盖度与训练轮数，而不是盲目加数据或加轮数。

常见失败点还包括：模型只输出一半 JSON 就截断，通常是未设最大生成长度或模板缺少结束标记；模型复述问题而不作答，常因数据中噪声样本过多或 prompt 掩码错误导致损失污染。一个更隐蔽的问题是训练用了打包（packing）却未按文档边界截断，导致一条样本的答案泄漏进下一条样本的 prompt，此时模型会「背出」后续内容而非真正作答。

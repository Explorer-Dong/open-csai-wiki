title: OPD
---

在线策略蒸馏 (Online Policy Distillation, OPD) 让当前学生策略采样，再以教师分布或反馈提供训练目标，把蒸馏从「离线数据」推进到「在线交互」。它的由来是经典知识蒸馏的局限：[Knowledge Distillation](https://arxiv.org/abs/1503.02531) 与 [Policy Distillation](https://arxiv.org/abs/1511.06295) 在预先收集的数据或教师生成的轨迹上训练，学生部署后一旦遇到自身错误前缀，就会进入训练时未见过的状态、发生分布偏移；[On-Policy Distillation of Language Models](https://arxiv.org/abs/2306.13649) 让教师直接修正学生自己采样出来的序列，使训练样本始终贴合学生当前的薄弱点。

## 快速开始

明确教师、学生、采样温度和权重同步周期。教师是更强的模型（或其分布），学生是要训练的策略；采样温度控制学生采样的随机性，温度越高探索越广但质量越低；权重同步周期指教师权重多久更新一次，若教师也在持续训练，需记录其版本。

先验证 KL 与质量指标，再扩大 rollout 集群。OPD 用学生自己采样的序列做训练，需要监控学生分布相对教师的 KL 散度，以及生成质量指标（如胜率、正确率），确认两者在合理区间后再加算力扩大规模。

搭建时把「采样」与「训练」解耦：采样节点负责 rollout 学生生成、向教师请求软目标，训练节点消费这些样本更新学生。两者解耦便于扩展，也便于在教师更新时平滑切换。

## 机制

相较固定离线数据，OPD 的样本来自当前学生分布，能覆盖其真实错误区域。离线蒸馏用固定数据集训练，学生只见过数据集里的样本；OPD 每次用学生自己采样的序列去问教师「更好应该怎样」，因此训练样本始终贴合学生当前的薄弱点，形成「采样 -> 教师指导 -> 更新 -> 再采样」的闭环。

训练目标通常是让学生分布逼近教师分布，形式为在学生采样的前缀上最小化学生与教师分布的差异，可抽象为：

$$
\mathcal{L}_{\text{OPD}} = \mathbb{E}_{y\sim\pi_\theta}\left[\sum_t \mathcal{D}\left(\pi_\theta(\cdot \mid x, y_{<t}),\ \pi_{\text{teacher}}(\cdot \mid x, y_{<t})\right)\right]
$$

其中 $\mathcal{D}$ 可按实现取前向 KL、反向 KL 或 token 级对数概率差。当 $\mathcal{D}$ 取 KL 散度时，目标即让学生在自己访问到的状态上匹配教师分布；若以教师 token 分布作为软标签做交叉熵，形式等价于 teacher forcing 式的序列级蒸馏。奖励类反馈也可以作为目标：教师（或验证器）对学生的采样给奖励，学生按强化学习更新，此时 OPD 与 [Agentic RL](./agentic-rl.md) 的边界接近。不能脱离算法定义把某个 KL 方向当成所有 OPD 的固定形式。

代价是需要控制教师成本、延迟与分布漂移。每次采样都要调用教师，教师越强成本越高；在线请求教师带来推理延迟；学生在训练中分布不断漂移，教师给出的软目标相对学生当前分布可能过时，需要同步周期或重放来缓解。

## 案例

学生对数学题生成多个解答，教师为 token 分布或答案提供软目标。学生先按一定温度采样若干条候选，教师对这些候选给出更优的 token 分布（软标签）或对答案质量给出反馈，学生据此更新，目标是最小化与教师分布的 KL 或提高教师评分的期望。

记录学生版本和教师版本，防止无法复现实验。每次采样与训练都要打上学生与教师的权重版本号，因为学生持续更新、教师也可能更新，任一变化都会改变训练样本与目标，缺了版本记录就无法复现或归因。

常见失败点包括：温度过低导致学生采样缺乏多样性、教师与目标失配（教师只擅长部分题型）、以及教师请求成为吞吐瓶颈。排查方向分别是提高采样温度或加探索奖励、限定教师擅长的任务范围、以及对教师做批处理或缓存以摊薄成本。

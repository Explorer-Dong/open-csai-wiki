---
title: Agentic RL
---

Agentic RL 在工具环境中优化多步决策轨迹，而不是只优化单次文本回答，它把强化学习从「生成一条回答」扩展到「在环境中完成一个任务」。它的由来是单轮 [RLHF](./rlhf.md) 的边界：当任务需要搜索、执行代码、调用 API 或操作浏览器时，每一步动作都会改变环境并影响后续观察，轨迹不再是孤立的回答序列，而是一条「决策 -> 观察 -> 再决策」的闭环。[WebGPT](https://arxiv.org/abs/2112.09332) 把浏览动作、环境观察与人类偏好放进同一任务，[ReAct](https://arxiv.org/abs/2210.03629) 确立了 Thought/Action/Observation 的交互范式，二者是 Agentic RL 的重要前身。

## 快速开始

先定义环境、动作空间、权限、终止条件和可验证奖励。环境可以是代码仓库、命令行、浏览器或 API 沙箱；动作空间是 Agent 可发出的命令或工具调用集合；权限限定它能读写哪些资源；终止条件定义何时一轮任务结束（任务完成、超时或步数上限）；可验证奖励是能自动判定的成功信号，例如隐藏测试是否通过。

在隔离沙箱中运行 rollout。沙箱必须能重置、能回放、能限制网络与文件系统，否则 Agent 可能破坏环境或泄露数据，且失败的轨迹无法复现。每条轨迹记录完整的状态、动作、观察、奖励序列，作为训练与调试依据。一条轨迹可写为：

$$
\tau = (s_0, a_0, o_1, s_1, a_1, o_2, \ldots, s_T)
$$

其中 $a_t$ 是文本或结构化工具调用，$o_{t+1}$ 是环境返回的观察，轨迹回报通常按折扣求和：

$$
R(\tau) = \sum_{t=0}^{T} \gamma^t r_t
$$

先用简单可判定任务跑通「采样轨迹 -> 计算奖励 -> 更新策略」的完整链路，再扩展到复杂任务。逐步放宽动作空间与任务难度，避免一开始就面对稀疏奖励与长时程决策叠加的困难。开源基础设施可参考 [Agent Lightning](https://arxiv.org/abs/2508.03680)（把既有 Agent 的运行事件转成可训练轨迹）与 [SWE-agent](https://arxiv.org/abs/2405.15793)（代码仓库环境中的 Agent）。

## 难点

工具返回会改变后续观察，奖励通常延迟且稀疏。与单轮问答不同，Agent 的每一步输出都会改变环境状态，进而影响下一步可用的信息，形成「决策 -> 观察 -> 再决策」的闭环；而奖励往往只在任务最终成功或失败时才给出，中间步骤几乎没有信号，导致信用分配困难。

需要处理信用分配、环境重置、轨迹成本和工具滥用四个问题。信用分配指把最终奖励归因到哪一步起了作用；环境重置指每次 rollout 后要把沙箱恢复到干净初始状态，否则状态残留污染后续采样；轨迹成本指长轨迹的采样与 token 开销大；工具滥用指 Agent 学会用无效或破坏性命令刷奖励。

这些难点叠加后，纯靠稀疏的最终奖励很难学习。常见缓解手段包括：提供中间奖励或过程监督、用更短的可解子任务做课程、限制步数上限、以及用 [GRPO](./grpo.md) 这类基于组内比较的更新减少方差。需要强调：只有同时存在环境交互轨迹、奖励或回报、信用分配与参数更新时，才构成参数更新型的 Agentic RL；仅在推理时执行工具循环（如 [ReAct](https://arxiv.org/abs/2210.03629) 或 [Toolformer](https://arxiv.org/abs/2302.04761) 的原始形式）并不自动等于强化学习。

## 案例

让 Agent 在临时仓库修复测试失败，奖励由隐藏测试和安全策略共同给出。每条轨迹中，Agent 读取仓库、运行测试、修改代码、再次运行测试，直到隐藏测试通过或步数耗尽；安全策略对危险命令（如访问网络、删除文件）给出负奖励或直接终止。

记录每步命令与环境版本，才能复现失败。把 Agent 执行的命令序列、环境初始状态、依赖版本一并保存，训练后若某条轨迹奖励异常，能按记录精确重放并定位是命令错误、环境状态问题还是奖励计算问题。

常见失败点包括：Agent 反复运行测试却不修改代码（用命令刷步数却不推进任务）、修改代码时破坏仓库、或在无网络沙箱中反复尝试联网下载依赖浪费时间。排查方向分别是收紧命令有效性检查、增加代码改动后的测试验证、以及用安全策略与步数上限约束无效探索。还要防止投机行为：若允许 Agent 修改测试文件，它可能删除断言来获得「测试通过」的奖励，因此隐藏测试必须隔离、依赖版本必须固定。

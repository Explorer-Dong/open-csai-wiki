---
title: 蒸馏
---

蒸馏用教师模型的输出或分布训练更小的学生模型，以降低部署成本。教师通常是参数量更大、能力更强但推理开销更高的模型，学生则面向资源受限的部署环境，目标是尽量保留教师能力的同时显著减小体积与延迟。这一思想由 Hinton 等人在 [*Distilling the Knowledge in a Neural Network*](https://arxiv.org/abs/1503.02531) 中系统提出，核心动机是：大模型输出的概率分布里藏着比硬标签更丰富的「暗知识」，例如教师虽然最终把「猫」判为正确，但它同时给「老虎」「豹」分配了可观概率，这种候选之间的相对关系是 one-hot 标签无法传递的，学生可以从中学习。

## 快速开始

开始蒸馏前，先明确目标任务和教师模型的具体版本，并把生成配置（温度、最大长度、采样方式）、提示模板和过滤规则固定下来，保证后续复现时数据口径一致。原始生成数据往往含噪声，需要按长度、格式和是否完成任务等条件过滤。

随后在教师上批量生成训练样本，保存「问题 -> 教师输出」及对应的 logits 或 soft label，再据此训练学生模型。评估阶段务必使用教师未见过的数据，同时记录学生相对基线的质量差、推理延迟和显存占用，综合判断蒸馏是否划算。

落地时优先复用现成实现而不是从零写训练循环，Hugging Face 的 [Distillation 教程](https://huggingface.co/docs/transformers/distillation) 提供了从教师生成数据到训练学生的完整流程。验证成功的标准至少包括：学生在目标任务上的指标与教师的差距落在可接受区间，同时推理延迟和显存占用确实低于教师；若两者只满足其一，说明蒸馏没有真正解决部署问题。

## 原理

学生可以学习不同粒度的监督信号。最简单的是「硬标签」，即把教师输出当作标准答案做监督微调；更丰富的是「软标签」，直接拟合教师对每个 token 的 logits 或经过温度缩放后的概率分布，让学生学到不同候选答案之间的相对关系。软标签的价值在于：即便某个候选不是最终答案，教师赋予它的概率大小仍反映了它与正确答案的接近程度，这是硬标签无法提供的信息。

温度系数 T 会软化概率分布。给定 logits $z$，带温度的 softmax 定义为：

$$
q_i=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}
$$

其中 $z_i$ 是第 $i$ 个候选的 logit，$T$ 是温度。T 越大，教师输出分布越平滑，能暴露更多次优答案的相对排序；T 越小则越接近硬标签。训练时通常用较大 T，推理时再回到 T=1。典型损失是学生与教师软化分布之间的 KL 散度，也可与真实标签的交叉熵混合使用：

$$
\mathcal{L}=\alpha T^2\cdot\text{KL}\left(q^T\,\|\,p^T\right)+(1-\alpha)\cdot\text{CE}\left(y,\,p^{T=1}\right)
$$

其中 $q^T$ 是教师在温度 $T$ 下的软化分布，$p^T$ 是学生在相同温度下的分布，$y$ 是真实标签，$\alpha$ 控制两项权重。乘 $T^2$ 是为了抵消 softmax 在低温下对梯度的缩放，使软标签项与硬标签项的量级可比较。

最小蒸馏损失可用如下代码表示：

```python
import torch
import torch.nn.functional as F

def distill_loss(student_logits, teacher_logits, labels, T, alpha):
    # 教师软化分布，detach 后作为固定目标
    soft_target = F.softmax(teacher_logits / T, dim=-1).detach()
    soft_logp = F.log_softmax(student_logits / T, dim=-1)
    soft_loss = -(soft_target * soft_logp).sum(dim=-1).mean()

    hard_loss = F.cross_entropy(student_logits, labels)

    return alpha * (T ** 2) * soft_loss + (1 - alpha) * hard_loss
```

这段代码对应上述损失公式，验证标准是 soft_loss 与 hard_loss 均随训练下降，且学生验证集指标逐步逼近教师。

蒸馏有效性受三方面限制：教师质量决定知识上限，数据覆盖决定学生的泛化边界，学生容量决定能吸收多少知识。教师答错、数据分布单一或学生太小，都会导致蒸馏收益下降，因此不能只追求模型变小而忽视这些前置条件。后续工作如 [DistilBERT](https://arxiv.org/abs/1910.01108) 和 [TinyBERT](https://arxiv.org/abs/1909.10351) 把这一思想从「输出分布」扩展到「中间层特征对齐」，说明蒸馏可以从输出层延伸到隐藏表示等多个粒度，粒度越深通常越需要额外对齐损失来稳定训练。

## 案例

某客服场景以通用大模型为教师，针对高频问题生成高质量答案，再用人工规则过滤掉拒答、答非所问和格式异常的样本，得到干净训练集。学生在过滤后的样本上训练，参数量显著低于教师。

上线前除了看平均相似度，还要专门验证三类行为：是否会在超出知识范围时正确拒答、是否会输出不安全内容、长尾问题上的表现是否明显退化。平均相似度可能被大量简单问题拉高，掩盖边缘样本的失败，因此必须分层评估。一个可操作的判定方法是先按问题难度或主题分桶，分别统计每桶的学生相对教师差距；若某个长尾桶出现明显退化，应回到数据覆盖环节补充该桶样本，而不是继续增加训练步数。
